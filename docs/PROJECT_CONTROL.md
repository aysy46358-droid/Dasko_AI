# سجل حالة المشروع وأولوياته

هذا سجل القرار والمتابعة لمشروع Dasko AI. يربط الحالة بأدلة محددة وحدود تحققها؛ نجاح فحص واحد لا يعني ضماناً مطلقاً أو جاهزية إنتاجية.

## لقطة التنفيذ الحالية

- تاريخ المراجعة: 2026-11-09.
- فرع العمل: `cursor/final-l10n-polish`، أُنشئ من `experimental-work` عند الالتزام `bcd3d593e0c385d616c4d7e33b110d7894a1a479`.
- تنفيذ هذا الفرع محلياً اجتاز `flutter pub get --enforce-lockfile` و`flutter gen-l10n` و`dart format` و`flutter analyze` و`flutter test`؛ نتائج الاختبارات شملت اختبارات التوطين الجديدة الأربعة. تحقق CI وبناء APK على GitHub لهذا التغيير والدمج إلى `experimental-work` لم يُسجلا بعد عند إعداد هذه اللقطة.
- `generate: true` كان موجوداً أصلاً في `pubspec.yaml` على نقطة الأساس؛ تم التحقق منه والإبقاء عليه. عُدّل قيد `intl` من `any` إلى `^0.20.3`؛ نسخة `pubspec.lock` المحلولة `0.20.3` وتطابق قيد Flutter 3.47.8.

## الحالة الحالية

- **البنية:** توجد طبقات `app`, `core`, `domain`, `features`, و`services`. عقد `AiEngine` واستخدامه في `SendMessage` يفصلان سياسة المحادثة عن adapter المحرك. الربط الحالي هو `MockAiEngine`؛ لا يوجد مزود ذكاء اصطناعي حقيقي موصول.
- **التوطين — مكتمل في فرع العمل، والدمج/CI معلّقان:** يدعم التطبيق العربية والإنجليزية بملفات ARB ومولّد Flutter `gen-l10n`. ملفات Dart المولدة متتبعة في Git تحت `lib/l10n/`. لم تعد هناك مراجع إلى `AppStrings` في `lib/` أو `test/`. `LocaleState.isInitialized` يجعل جذر التطبيق ينتظر استعادة اللغة قبل إظهار المحتوى؛ آخر اختيار أثناء القراءة الأولية يتقدم على القيمة المخزنة، وتُسلسل عمليات الحفظ. لا يضيف التطبيق `Directionality` يدوياً؛ delegates القياسية تحدد RTL/LTR من الـlocale.
- **اختبارات التوطين الجديدة:** `test/l10n_test.dart` يغطي استعادة اللغة قبل عرض الواجهة، وسباق التبديل أثناء القراءة الأولية، والتحول بين RTL/LTR، ونص ARB ديناميكي عبر placeholder مولد. اجتازت الاختبارات محلياً على Flutter 3.47.8؛ لم يُسجل بعد تشغيل CI على هذا التغيير.
- **الثيم والروبوت:** الخيارات Light/Dark/Neon محفوظة best-effort. الروبوت الحالي صورة poster ثنائية الأبعاد مع تلاشي شعاعي لحوافها وتوهج يستخدم لون الثيم (blur 25) ونبض عند حالة التفكير. صحة العرض البصري والأداء على هاتف فعلي لا تثبتها اختبارات الودجت وحدها؛ يلزم التحقق على الجهاز.
- **Crashlytics — مهيأ في المصدر؛ الاستقبال غير متحقق:** Firebase Core اختياري عند الإقلاع، وتقارير Crashlytics غير القاتلة مهيأة بعد تهيئة Firebase. مصدر الكود يمرر نوع الخطأ ومصدره الثابت وإطارات المكدس لا نص الاستثناء الخام أو محتوى المحادثة أو مفاتيح API أو معرّفات المستخدم. وصول الحدث فعلياً إلى Console/جهاز لم يُتحقق منه.
- **Firebase:** لا يوجد تكامل Auth أو Firestore أو Realtime Database أو Storage أو Functions أو App Check في مسار التطبيق. لا توجد قواعد Firebase قابلة للنشر ضمن الملفات التي تمت مراجعتها؛ حالة القواعد والإنفاذ في Console تحتاج تحققاً مستقلاً قبل إضافة اعتماد على هذه الخدمات.

## إعداد التوطين

- المصدر: `lib/l10n/app_en.arb` و`lib/l10n/app_ar.arb`؛ إعدادات المولد في `l10n.yaml`؛ المخرجات المتتبعة: `app_localizations.dart` وملفات اللغة تحت `lib/l10n/`.
- `pubspec.yaml` يحتوي `flutter: generate: true` و`intl: ^0.20.3`. قيد `intl` مطابق لـ`flutter_localizations` ضمن Flutter 3.47.8، والـlockfile يحل النسخة `0.20.3`.
- عند تعديل ARB: شغّل `flutter gen-l10n`، راجع فرق الملفات المولدة، ثم نفّذ format/analyze/tests. CI الحالي يسبق التنسيق والتحليل والاختبارات بتوليد الترجمات بعد حل الاعتمادات.
- أضف النصوص الديناميكية كـplaceholders موصوفة في ARB، ولا تركّب الجمل المترجمة بضم سلاسل يدوياً.

## الأولويات المفتوحة

1. **CI والدمج:** شغّل/راجع فحوص GitHub على commit هذا التغيير، وتأكد من Build APK على `experimental-work` بعد الدمج. لا يعتبر التحقق المحلي بديلاً عن فحص GitHub المستهدف.
2. **Firebase وقواعد الوصول:** افحص إعدادات Firebase Console وقواعد الوصول وApp Check قبل إضافة أي اعتماد على خدمات البيانات؛ App Check لا يحل محل قواعد التفويض.
3. **Crashlytics:** نفّذ حدثاً غير قاتل آمناً على بيئة اختبار وتحقق من ظهوره في Console، مع مراجعة حمولات البيانات والاحتفاظ والإفصاح. لا تستخدم محتوى محادثة أو معرفاً حساساً.
4. **محرك AI حقيقي:** لم يبدأ. قبل Gemini أو غيره، حدد حدّ الاعتمادات خارج APK، وتمثيل history، والمهلات، وسياسة الخصوصية والتسجيل، والاختبارات، وحدود الحصة والتكلفة المجانية.
5. **الروبوت والواجهة:** اختبر fade/glow والثيمات والحركة ولوحة المفاتيح وحالة فشل تحميل الصورة على الأجهزة الفعلية؛ لا توجد قياسات أداء جهاز لهذه التغييرات.
6. **الصوت:** الصوت وTTS مقتصران على تدفق الترحيب؛ لم تُبنَ بعد خدمة صوت للمحادثة.

## قاعدة العمل

- اعمل على الفرع المصرح به لهذه المهمة، ولا تنقل التغييرات إلى `main` دون موافقة صريحة.
- قبل التعديل، تحقق من الفرع والرأس ونظافة الشجرة واقرأ الملفات المتأثرة.
- بعده، راجع الفرق وشغّل الفحوص ذات الصلة؛ عند الفشل، عالج السبب ولا تصف المهمة بالناجحة قبل ظهور نتيجة.
- ميّز بين مراجعة المصدر والاختبارات المحلية وCI وتجربة الجهاز والتحقق من Firebase Console.
